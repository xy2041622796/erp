# 期间结转科目分类、固定科目查询与前端核算修复

## 背景
- 会计科目类别当前使用 1~5：资产、负债、权益、成本、损益。
- 原期间结转逻辑把费用类写死为 `subject_type = 6`，导致费用结转明细取不到数据。
- 期间结转还会固定读取 `3103 本年利润`、`3104006 未分配利润`、`5801 所得税费用` 等科目。

## 修复内容
- 修改文件：`src/api/erp/finance/period/index.ts`
- 修改页面：`src/views/finance/cwhs/treatment/period/index.vue`
- 将期间结转的损益科目来源统一改为 `subject_type = 5`（损益）。
- 按科目 `balance_direction` 拆分：
  - `2 / 贷 / credit` 归类为收入科目
  - `1 / 借 / debit` 归类为费用科目
- 固定科目查询保持 `Bil_Subject_Info.account_set_id` 账套口径不变。
- `querySubjects` 查询科目时统一追加 `account_set_id` 条件，避免从其他账套混入损益科目或固定科目。
- `queryTableItems` 不支持也不传递 `fields`，不设置 `table.Fields`，不下发排序字段，所有查询由后端按默认字段和默认顺序返回，避免 Fields/OrderType/Order 导致请求项错误或字段裁剪。
- 多个固定科目编码查询时，不再先查一批数据后在前端过滤；改为向后端下推 `or(subject_number = ... )` 精确条件。
- `queryTableItems` 不设置默认大分页，避免后端因分页参数过大返回“请填写合适的分页参数”。固定科目通过精确条件保证返回范围足够小。
- 期间结账弹窗增加“前端核算公式”和“前端核算明细”，直接展示当前前端按已查询数据计算出的收入、费用、利润和分录方向。

## 根因说明
- 数据库中存在 `3103 本年利润`，且字段 `Bil_Subject_Info.account_set_id` 为当前账套口径。
- 原 `querySubjects` 在 `subjectNumbers.length > 1` 时没有把多个科目编码条件下推到后端，而是查询账套下的一批科目后再前端过滤。
- 同时科目查询没有统一追加 `account_set_id` 条件，可能导致前端核算使用跨账套科目池。
- 查询不应传递 `Fields` 或排序字段；科目核算需要完整字段，凭证明细查询也不应因排序字段触发请求项兼容问题。
- 如果后端 GetData 默认返回列表里不包含 `3103`，最终 `buildSubjectBuckets` 会误判为“未找到科目 3103（本年利润）”。
- 不能用超大分页强行兜底，因为后端会校验分页大小并报“请填写合适的分页参数”。

## 修复后的结转口径
- 收入结转：统计损益类中余额方向为贷的末级科目，按 `贷方 - 借方` 汇总。
- 费用结转：统计损益类中余额方向为借的末级科目，按 `借方 - 贷方` 汇总。
- 前端弹窗展示科目级核算明细：类别、科目编码、科目名称、结转金额、生成分录方向。
- 期间结转凭证仍结转到 `3103 本年利润`。

## 影响范围
- 期间结转预览页面的“收入结转明细”“费用结转明细”
- 期间结账弹窗的前端核算公式与核算明细
- 生成期间结转凭证的分录明细
- `3103 本年利润`、`3104006 未分配利润`、`5801 所得税费用` 等固定科目读取
- 本期利润计算结果

## 验证建议
1. 打开财务 -> 期间结转，选择有损益凭证的期间。
2. 预览时确认：
   - 收入结转明细只出现余额方向为贷的损益科目
   - 费用结转明细只出现余额方向为借的损益科目
   - 前端核算公式为“本期收入合计 - 本期费用合计 = 本期利润”
   - 前端核算明细中的科目均属于当前账套
   - 不再误报“未找到科目 3103（本年利润）”
   - 不再出现“请填写合适的分页参数”
   - 请求体中不再出现 `Fields`、`OrderType`、`Order`
3. 生成结转凭证后确认分录：
   - 收入科目借记，贷记 3103
   - 费用科目贷记，借记 3103
