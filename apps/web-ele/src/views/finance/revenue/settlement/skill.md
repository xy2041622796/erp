# 收入结算页面 skill

## 页面入口
- 路径：`apps/web-ele/src/views/erp/finance/revenue/settlement`
- 页面文件：`index.vue`
- 弹窗表单：`modules/form.vue`
- 明细子表：`modules/item-form.vue`
- 收款计划详情弹窗：`modules/contract-plan-detail-dialog.vue`
- 表单/表格配置：`data.ts`

## 页面能力
- 支持新增收入结算与退款结算。
- 列表页已将结算主体拆分为“主体类别 + 主体编码”两列展示：
  - 合同主体类别列显示“按合同 + 第N期”，主体编码列显示合同号；
  - 订单主体类别列显示“按订单 + 共N单（多单时）”，主体编码列显示首单号/订单号。
- 合同主体原有的期次展示逻辑保留，不因订单主体改造而改变。
- 退款标签仍保留在日期/编号区域，不和主体标签混杂。

## 关键交互规则
- 列表优先读取主表 `subject_type` 字段判断主体类型。
- 当 `subject_type` 为空时，按 `contract_id` 是否存在兜底判断：
  - 有合同按合同主体；
  - 无合同按订单主体。
- 订单主体摘要来自 `Bil_Settlement_Order`：
  - 首单号取第一条关联订单的 `order_no`；
  - 单据数量按关联订单条数统计。

## 新增/编辑表单主体切换
- 表单顶部新增 `主体类型` 单选按钮组：
  - `按合同`
  - `按订单`
- `主体选择` 输入框会根据主体类型动态切换选择器：
  - 选择 `按合同` 时，点击后打开合同选择弹窗；
  - 选择 `按订单` 时，点击后打开销售订单选择弹窗。
- 切换主体类型时，会清空当前主体、来源产品信息与合同期次摘要，避免混用旧数据。

## 收款计划详情
- 合同主体下，原“查看合同详情”入口已改为“查看收款计划详情”。
- 点击后展示当前合同下的全部收款计划，并高亮当前结算关联的计划期次。
- 计划数据来源：合同子表 `Bil_Contract_settlement_plan`。
- 当前结算与计划的关联来源：`Bil_Settlement_Plan_Rel`。

## 产品信息展示规则
- 原“订单”子表改为“产品信息”展示区。
- 当主体类型为 `按合同` 时：
  - 根据所选合同加载合同侧的来源产品/来源订单信息；
  - 用于展示产品名称、规格/说明、单位、数量、金额、税额、来源单号等。
- 当主体类型为 `按订单` 时：
  - 根据所选销售订单加载该订单下的产品明细；
  - 产品信息列表与合同主体展示口径保持一致，只读展示，不提供额外操作列。

## 保存口径
- 主表保存：
  - `subject_type` 记录当前主体类型；
  - `contract_id` 仅在 `按合同` 时保存；
  - `product_id / product_name` 仅在 `按订单` 时保存，用于记录所选订单。
- 订单主体保存时，仍会向 `Bil_Settlement_Order` 写入一条订单关联摘要，保证后续列表摘要与兼容逻辑可用。
- 合同主体保存时，当前主要以主表合同信息为准，产品信息用于展示与金额汇总。
- 合同主体创建成功后，会同步写入 `Bil_Settlement_Plan_Rel`，把结算单与当前收款计划关联起来。

## 当前实现说明
- 新增收入结算时，若未显式传入 `subject_type`，接口层会按“有合同=合同主体，无合同=订单主体”自动写入。
- 订单主体列表展示依赖结算订单表聚合，不要求额外新增摘要字段。
- 数据库历史数据可通过 SQL 一次性回填 `subject_type`。

## 收款提报联动
- 收入结算审批后，状态进入“待收款”。
- 列表在 `status=20` 且为普通收入结算（`settlement_type=0`）时，将“审批”按钮切换为“生成提报单”。
- 合同主体点击“生成提报单”时，会优先读取当前结算关联的收款计划：
  - 若存在关联计划，则本次提报金额优先使用计划金额；
  - 同时把计划期次、计划日期、计划金额写入提报备注预设；
  - 再预带客户、项目、合同与收款账户。
- 若当前结算未关联计划，则回退为按结算单的可收金额生成提报单。

## 状态默认值
- 新建收入结算默认状态统一为 `10=待审批`。
- 前端弹窗初始化与接口创建兜底都按待审批写入，避免因默认值为 `0` 导致列表误显示为“已完成”。

## 提报成功后状态联动
- 收入结算审批后状态进入 `20=待收款`。
- 新增收款提报成功后，关联的收入结算单状态会自动更新为 `30=已完成`。
- 该联动不区分入口，既适用于收入结算页面直接生成提报单，也适用于收款提报页面手工新增后选择业务单据。

## 产品信息列口径
- 新增/编辑收入结算时，产品信息表展示列调整为：
  - `产品名称`
  - `规格/说明`
  - `单位`
  - `数量`
  - `单价`
  - `未税金额`
  - `税额`
  - `含税合计`
  - `来源单号`

## 收款账户选择
- 新增/编辑收入结算时，`收款账户` 已改为与销售订单一致的账户下拉选择。
- 下拉数据来源：`#/api/erp/finance/account` 的 `getAccountSimpleList`。
- 表单保存值为账户主键 `rowid`。

## 生成提报单时预带收款账户
- 从收入结算点击“生成提报单”时，除客户、项目、合同和业务单据外，还会把收入结算中的 `收款账户` 一并预带到收款提报。

## 收入结算状态口径
- 收入结算状态现统一为：
  - `10=待审批`
  - `20=待提报`
  - `25=收款中`
  - `30=已完成`
- 审批通过后，结算单从 `10` 进入 `20`。
- 新增收款提报成功后，结算单推进到 `25`，表示已进入收款流程但尚未全部完成。
- 收款提报在列表中“确认”后，系统会按照本次核销金额扣减 `receive_balance`：
  - 若余额仍大于 0，则保持 `25=收款中`；
  - 若余额变为 0，则更新为 `30=已完成`。
- 收款提报选择结算单时，仅允许选择状态为 `20` 或 `25` 的普通收入结算单。

## 提报与确认联动
- 新增收款提报保存成功后，仅将关联收入结算单状态推进到 `25=收款中`。
- 收款提报列表中的“确认”按钮才会真正回写收入结算的 `receive_amount`、`receive_balance` 与状态。
- 列表中的“核销状态”按金额实时推导：
  - 实收金额 = 0 -> `未核销`
  - 实收金额 > 0 且余额 > 0 -> `部分核销`
  - 余额 = 0 -> `核销完成`

## 确认后回写金额字段
- 收款提报“确认”后，系统会回写收入结算：
  - `receive_amount`（实收金额）
  - `receive_balance`（余额）
  - `ticket_amount`（当前按余额口径同步显示）
  - `status`（`25=收款中` / `30=已完成`）
- 列表“核销状态”按金额实时推导：
  - 实收 = 0 -> 未核销
  - 实收 > 0 且余额 > 0 -> 部分核销
  - 余额 = 0 -> 核销完成

## 删除级联子表
- 收入结算删除时，会同时逻辑删除以下子表/关联表数据：
  - `Bil_Settlement_Order`（订单子表）
  - `Bil_Settlement_Plan_Rel`（计划关联表）
- 避免出现主表删除后，订单明细或计划关联残留的问题。
