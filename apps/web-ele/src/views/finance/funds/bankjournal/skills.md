# 银行日记账（finance/funds/bankjournal）

## 页面入口
- 路由：`/finance/funds/bankjournal`
- 页面文件：`src/views/finance/funds/bankjournal/index.vue`
- API 文件：`src/api/erp/finance/funds/bankjournal.ts`
- Skill 文件：`src/views/finance/funds/bankjournal/skills.md`

## 页面能力
- 按银行账户、日期范围查看银行日记账，初始化余额行固定第一行，合计行固定最后一行。
- 顶部工具栏不再提供“新增一行”按钮，页面加载、切换账户、刷新筛选条件后也不再自动创建空白候选行。
- 银行账户下拉来自资金设置 `Bil_Funds_Account`，展示格式为：`编号 + 银行名称 + 账户名称`。
- 银行账户下拉项也按相同格式展示，并保留按绑定科目编码计算的层级缩进。
- 收支类别列通过 `fetchIoTypes()` 将 `io_type` 映射为类别名称，映射不到时不展示长 ID。
- 编辑行防误新增：保存时如果前端行 `id` 缺失，会按 `capital_account_rowid + journalNo` 或 `lingma_sys_key` 查询原日记账记录，查到后转为更新。
- 保存日记账行防重复：新增时不提交前端残留 `journalNo`，落库后由编码规则生成；保存成功后立即回填返回 `id`。
- 初始化余额行不参与普通删除、关联凭证和生成凭证；表格选择列仅允许选择明细行。
- 页面工具栏已移除“银企互联”入口，不保留占位按钮。
- 初始化余额保存时会补齐 `account_name`、`account_code`、`account_kind` 后再调用 `saveFundsAccount()`。

## 使用到的 API
- 银行账户：`fetchBankAccounts()`，来自资金设置 `Bil_Funds_Account`，账户类型为“银行存款”和“其他货币资金”。
- 日记账列表：`fetchBankjournalList({ accountId, start, end, showAll })`，读取 `Bil_Bank_Journal`。
- 行保存/删除：`saveBankjournalRow()`、`deleteBankjournalRow()`。
- 初始化余额保存：`saveFundsAccount()`。
- 收支类别/往来单位：`fetchIoTypes()`、`fetchCounterparties()`。
- 关联凭证：`linkBankjournalVoucher()`。
- 凭证查询：`getVoucherPage()`、`getVoucherDetails()`。

## 本次交互规则
- 已移除工具栏“新增一行”按钮。
- `reload()` 仅加载后端返回的明细，不再调用 `ensureDefaultCandidateRow()` 自动追加空白行。
- 已有明细行编辑保存成功后，不再调用 `ensureBlankRowAfter()` 插入下一条空白草稿行；新增草稿行保存成功后仍会插入下一条，保持连续录入。
- 已有行仍可点击进入编辑态，填写完整后失焦自动保存。

## 打印列表
- “打印列表”按钮可点击。
- 复用 `buildBankjournalPrintHtml` 和页面隐藏 iframe 打印方式。
- 打印标题固定为“银行日记账”。
- 打印内容包含账户、期间、打印时间、期初余额、明细、收入合计、支出合计和期末余额。

## 导入导出
- 页面工具栏启用“导入 / 导出”下拉按钮。
- 导入支持下载 Excel 模板，选择 .xlsx/.xls 文件导入当前选中的银行账户。
- 导出支持导出当前筛选结果、导出当前银行账户全部流水。

## 样式说明
- 银行账户下拉项使用 `account-option-tree` 展示，编号使用次要色，银行名称和账户名称同一行展示。
- 工具栏保持紧凑横向布局，空间不足时按现有响应式规则兜底。

## 账户下拉样式
- 银行账户下拉展示为 `编码 - 名称`，与现金日记账账户下拉保持一致的行高、绿色账户名称和底部操作区。
- 下拉底部包含“全部账户”“显示禁用账户”开关和“⊕新增账户”入口。
- “显示禁用账户”开启后重新加载账户列表，账户来源包含禁用账户；关闭后仅展示启用账户。
- “⊕新增账户”跳转资金账户设置页 `/finance/funds/settings`。
- 账户下拉弹层宽度固定为 226px，避免 Element Plus 下拉弹层被底部操作区撑满页面宽度。
- 账户下拉使用系统主题色 `var(--el-color-primary)`；存在子级的上级账户不显示编号且禁用选择，只能选择末级账户。
- 账户下拉弹层宽度调整为 250px，底部操作区不再右侧溢出。
- 账户下拉与选中显示均不展示账户编号，只展示银行名称和账户名称；上级账户继续禁用选择。
- 账户下拉底部“⊕新增账户”不再跳转资金设置页，直接打开银行账户新增弹窗；弹窗包含银行、账户名称、银行卡号、期初余额、备注，保存后刷新账户下拉并选中新账户。
- 页面加载、切换账户或刷新筛选条件后，明细区会自动保留一条空白候选行；顶部“新增一行”按钮仍保持移除。
- 已有明细行编辑保存成功后，不再在当前行下方自动插入空白草稿行，保存后退出编辑态，避免修改完成后新增下一项。
- 新增草稿行保存成功后，仍会在当前行下方插入一条空白草稿行并进入编辑态，保持连续录入能力。
- 行编辑失焦时，如果日期、摘要、收支类别、收入或支出金额均已填写，会立即调用保存接口自动保存；如果行已录入但必填项缺失，会提示缺失项并保持编辑态。
- 新增明细保存成功后，保存接口返回自动生成的日记账序号，页面立即回填 `journalNo`，不需要再次刷新才能看到序号。
- 操作列提供“上插”“插入”“删除”：可在指定银行日记账明细行上方或下方插入一条空白草稿行，插入后自动进入编辑态；结转期间禁止插入。
- 若当前行所属期间已关账/结转，操作列不展示“上插”“插入”，仅保留已允许的操作。
- 操作列插入行入口只展示“插入”，用于在当前银行日记账明细下方插入空白草稿行；不再展示“上插”。
- 顶部工具栏不再展示“显示全部”复选框。
- 收入（借方）和支出（贷方）列宽调整为 165px，金额输入框使用列内自适应宽度，避免内容超出单元格。
- 银行账户下拉加载时不再自动同步会计科目，仅读取已有资金账户；如需同步请到账户设置页手动点击“同步科目”。

## 收支类别方向规则
- 收支类别下拉和列表展示会按类别方向增加前缀：收入类展示为 `收-类别名称`，支出类展示为 `支-类别名称`。
- 类别方向优先读取 `categoryType/category_type`：`1` 为收，`2` 为支；字段缺失时按类别名称中的收入/收款/支出/付款做兜底判断。
- 自动保存前会校验金额方向：填写收入（借方）金额时必须选择“收”类，填写支出（贷方）金额时必须选择“支”类；不符合时会提示并保持编辑态。

## 收支类别下拉新增入口
- 现金/银行日记账明细行编辑时，收支类别下拉底部展示 `+点击添加`。
- 点击 `+点击添加` 直接打开收支类别新增弹窗，复用 `src/views/finance/funds/inexpcate/modules/form.vue`。
- 新增类别保存成功后自动重新读取 `fetchIoTypes()`，刷新当前日记账页面的收支类别下拉选项。
- 新增类别的收入/支出方向按当前行金额推断：收入金额大于 0 默认新增收入类，支出金额大于 0 默认新增支出类；未填写金额时默认新增收入类。

## 凭证关联下拉

## 插入行排序规则
- 银行日记账原有分组和排序规则保持不变，不因为新增“随时插入”能力而改为全局按插入排序展示。
- 单据/日记账编号继续按原编码规则生成，不通过前端插入逻辑改号。
- 手动“插入”产生的新行会记录三个持久化信息：`LM_JOURNAL_SORT`、`LM_JOURNAL_PREV`、`LM_JOURNAL_NEXT`，统一写入日记账 `description`。
- `LM_JOURNAL_PREV` 保存插入位置前一行锚点，`LM_JOURNAL_NEXT` 保存后一行锚点；刷新后接口先按原分组和排序得到基础顺序，再按 prev/next 锚点把插入行放回原位置。
- 如果锚点行仍存在，插入行刷新后保持在 prev 下方、next 上方；如果锚点缺失，则回退使用 `LM_JOURNAL_SORT` 和原排序规则。
- 普通新增、普通编辑和没有插入标记的历史数据继续走原有分组和排序兜底排序。
## 新增银行账户会计科目层级
- 新增银行账户弹窗的“会计科目”下拉仅展示启用的 `1002 银行存款` 和 `1012 其他货币资金` 及其下级科目。
- 科目按 `subject_number` 进行纯字符串编码排序，不使用 numeric 自然排序；这样 `1002001 交通银行` 会紧跟在 `1002 银行存款` 下方，`1012001 微信` 会紧跟在 `1012 其他货币资金` 下方。再按编码段规则 `4-3-2-2` 计算层级缩进。
- 存在下级的父级科目在下拉中加粗展示并禁用选择，新增账户只能选择末级科目。
- 选择科目后同步写入 `subject_id`、`subject_code`、`subject_name`，保存资金账户时落到 `Bil_Funds_Account`。
- 银行日记账明细表“收支类别”列宽调整为 170px，编辑态下拉宽度调整为 160px，避免类别名称和清空图标挤压。
- 银行日记账自动保存时不再强制要求收支类别维护会计科目；未维护科目不再提示“收支类别科目”，仅继续校验收支类别本身、金额方向和银行账户科目。
- 银行日记账手动插入行在编辑金额时不再立即执行 `moveRowToAmountGroupTail()` 移到分组尾，仅重算余额；避免插入行编辑态被重排打断，保证失焦后继续走 `onEditorBlur -> saveRow` 自动保存。

- 顶部筛选区再次微调：银行账户选择框加宽到 `158px`（1024px 以下 `152px`），筛选区日期列同步缩窄，减少日期控件横向占位并提升账户名称可读性。

- 日期范围控件改为强制收窄：覆盖 Element Plus daterange 默认宽度、最小宽度和最大宽度，桌面宽度为 `220px`，1024px 以下为 `210px`，确保视觉上实际变窄。

- 日期范围控件在强制收窄基础上略微调宽：桌面宽度调整为 `220px`，1024px 以下调整为 `210px`，兼顾日期可读性和筛选区占位。

## 排序与收支分类
- 银行日记账不再按收入/支出做大分类排序；修改收入、支出金额或收支类别时保持当前行所在位置，只重新计算余额。
- 手动插入排序仍按 description 中的 `LM_JOURNAL_PREV` / `LM_JOURNAL_NEXT` 锚点恢复位置，不改 journalNo 生成规则。

- 刷新排序时仅手动插入行的 `LM_JOURNAL_PREV` / `LM_JOURNAL_NEXT` 锚点会启用 `LM_JOURNAL_SORT`；普通历史行即使残留旧 sort 标记也会忽略，避免旧收支分组顺序继续生效。

- 打印银行日记账列表时，表格 `thead` 使用 `display: table-header-group`，跨页打印到第二页及后续页时会重复展示表头。

- 打印银行日记账列表时，列集合跟随页面“显示全部”：未开启时只打印当前常规可见列，不打印项目、部门、往来单位账号、往来单位开户行、结算方式、票据号、备注、交易流水号等扩展列；开启后才打印扩展列。

- 打印银行日记账列表时，会在当前可打印列范围内再次过滤空列：除收入、支出、余额等存在合计/余额含义的金额列外，所有明细行都没有内容的列不打印。

- 打印银行日记账列表时，单据编号列排在最前面；初始化余额、合计等行说明仍落在摘要列。

- 批量打印收/付款凭据时，每张 A4 纸默认排两张凭据；奇数张最后一张单独占下半页空间，不再一张凭据占一整页。

- 收支类别下拉按当前行金额方向过滤：收入行只展示收类，支出行只展示支类；收支类别按后端排序字段排序，无排序字段或新增项排在对应分类最后。

- 打印日记账列表跨页时，页面容器允许自然分页，并强制 `journal-table thead` 使用 `table-header-group`，确保第二页及后续页继续展示表头。

- 删除银行日记账行使用 DataTable `deleted` 通道；删除前会按当前行 `id` 回查，并校验账户与单据编号一致，避免误删其他链路内容。

- 批量操作中的“指定收支类别 / 指定往来单位 / 指定项目 / 指定部门”均使用下拉选择；确认后会批量写回所选行并调用保存接口持久化。


## 新增/编辑识别规则
- 页面保存银行日记账明细时，先根据当前行 `id` 判断是否为新增草稿行。
- 新增草稿行调用 `saveBankjournalRow()` 时会传入 `forceAdd: true`，并清空 `id`、`journalNo`、`lingma_sys_key` 后再提交，避免新增行因残留编号或系统 key 被识别为已有记录。
- `saveBankjournalRow()` 接收 `forceAdd` 后跳过 `journalNo` / `lingma_sys_key` 的旧行反查，直接走 `added` 通道并生成新的 UUID 主键。
- 已有明细行仍以 `id` 为准走编辑；只有非强制新增且 `id` 缺失时，才保留按 `journalNo` 或 `lingma_sys_key` 反查旧行的兜底逻辑。


## 银行日记账列表查询分页规则
- `fetchBankjournalList()` 查询 `Bil_Bank_Journal` 明细列表时不再传 `PageParam`，与现金日记账 `fetchCashdayList()` 保持一致。
- 底层 `queryTable()` 增加 `noPageParam` 开关；银行日记账列表查询使用该开关直接不传分页参数。
- 按 id 反查、编辑防重复等精确查询仍保留原分页参数，避免影响其他小范围查询。
