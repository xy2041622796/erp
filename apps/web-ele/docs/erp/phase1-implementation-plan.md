# 领码ERP第一阶段实施方案

## 1. 实施确认结论

本阶段正式确认以下实施决策：

- 首批实施模块确认：工作台、人力资源、OA办公、财务管理。
- 财务管理作为第一个样板模块，先做落地实施。
- 不单独输出“旧新映射表”作为独立交付物，改为在模块实施文档中直接维护迁移清单与路由迁移清单。
- 现状树与目标树统一以 Markdown 形式存储在 `lmbill/apps/web-ele` 仓库目录中。
- 第一阶段以“导航统一 + 前端入口迁移 + 路由迁移 + 页面归属迁移”为主，不先做数据库业务逻辑大重构。

---

## 2. 第一阶段总体目标

第一阶段不是纯菜单调整，而是一次“导航结构迁移 + 前端入口迁移”的系统工程，目标如下：

1. 在产品层面形成统一的 ERP 导航体系。
2. 在前端层面完成菜单、路由、面包屑、标签页、快捷入口的同步迁移。
3. 在业务层面完成首批模块归口，尤其是财务管理的前后台拆分。
4. 在实施方式上先跑通财务样板模块，再复制方法论到人力资源、OA办公、工作台。

## 4. 实施原则

### 原则一：先样板后复制
先在财务管理中跑通导航重构、路由迁移、页面归属迁移、前端兼容策略，再复制到其他模块。

### 原则二：先文档冻结再改代码
现状树、目标树、模块实施文档、路由迁移清单先落库，再进入代码改造。

### 原则三：不单独做旧新映射表
不再维护独立的旧新映射台账文件，改为每个模块文档中直接维护：
- 现状节点归类
- 目标节点结构
- 路由迁移清单
- 页面归属调整清单

### 原则四：迁移以路由为主线
由于前端与导航高度绑定，迁移的切入点不是菜单名称，而是：
- 页面路由
- 菜单挂载
- 面包屑归属
- 快捷入口归属
- 待办/通知跳转路径

### 原则五：先支持兼容，再做收口
第一阶段允许新旧入口并行，但兼容信息不再以“旧新映射表”独立管理，而是以路由兼容规则内嵌在模块实施方案中。

## 6. 正式实施步骤

### 步骤 1：冻结现状树和目标树
输出并确认：
- 现状导航结构
- 目标导航结构
- 财务管理目标结构

完成标志：文档冻结，可进入开发设计。

### 步骤 2：财务管理样板实施设计
输出并确认：
- 财务现状结构拆解
- 财务目标结构
- 财务路由迁移方案
- 财务前端改造范围
- 财务联调清单

完成标志：财务模块实施边界明确。

### 步骤 3：前端路由迁移设计
围绕财务管理先完成：
- 菜单路由归口
- 面包屑生成规则
- 标签页兼容规则
- 快捷入口跳转规则
- 待办通知跳转规则

完成标志：前端可支撑财务模块新导航。

### 步骤 4：财务代码改造
实际进入代码：
- 财务导航入口重挂
- 财务页面路由调整
- 财务菜单归口调整
- 财务面包屑改造
- 财务标签页修正

完成标志：财务模块可在目标导航下完整运行。

### 步骤 5：财务联调与回归
验证内容：
- 菜单显示正确
- 页面打开正确
- 权限不串域
- 面包屑正确
- 待办跳转正确
- 报表入口正确
- 旧入口可过渡访问

完成标志：财务作为样板模块通过。

### 步骤 6：复制到工作台 / 人力资源 / OA办公
复制财务方法论：
- 先结构文档
- 再路由迁移文档
- 再代码迁移
- 再联调

完成标志：首批四个模块迁移完成。

### 步骤 7：进入第二批模块
再处理：
- 进销存
- 系统管理

---

## 7. 财务样板模块为什么先做

财务管理最适合作为样板模块，原因如下：

1. 现状结构最复杂，能完整验证迁移方法。
2. 同时包含前台业务、后台核算、设置、报表、资金、发票、结算等典型问题。
3. 财务模块一旦跑通，HR、OA、工作台的实施难度会明显下降。

---

## 8. 下一步正式开始实施的动作

从现在开始，正式实施按下面顺序推进：

1. 确认并冻结现状树文档。
2. 确认并冻结目标树文档。
3. 进入财务管理样板实施文档评审。
4. 由前端开始财务模块路由改造设计。
5. 由产品和前端共同确认财务菜单、面包屑、快捷入口、待办跳转归属。
6. 财务模块通过后，再复制到工作台、人力资源、OA办公。

---

## 9. 本阶段的实施边界说明

本阶段重点是“开始迁移”，不是“一次性迁完”。因此当前启动动作定义为：

- 已经开始实施设计。
- 已经开始财务模块样板设计。
- 已经开始路由迁移设计。
- 还未进入全量代码改造。

也就是说，当前状态为：

> 第一阶段实施已经启动，当前正处于“财务样板模块实施设计与路由迁移设计”阶段。
