# 财务管理样板模块实施方案（含路由迁移）

## 1. 文档定位

本文件是第一阶段第一个样板模块的正式实施文档。

本文件不单独维护“旧新映射表”，而是直接在模块内定义：

- 财务现状结构拆解
- 财务目标结构
- 财务路由迁移方案
- 财务前端实施顺序
- 财务联调与上线规则

---

## 2. 财务模块为什么先做

财务管理现状最复杂，具备完整的样板价值：

1. 同时存在业务单据类、后台核算类、设置类、报表类入口。
2. 同时存在同义菜单、容器菜单、页面菜单。
3. 同时涉及菜单、路由、面包屑、权限、待办、报表、快捷入口。
4. 如果财务样板跑通，后续人力资源、OA办公、工作台复制成本最低。

---

## 3. 财务现状结构拆解

当前数据库中，财务管理一级下已确认的现状节点包括：

- 业务维度
- 往来账款
- 仪表盘
- 会计处理
- 报销
- 资金
- 报表
- 期末结转
- 设置
- 工资管理
- 凭证
- 资金管理
- 资产
- 发票管理
- 支出结算
- 账户管理
- 收入结算
- 帐簿

### 3.1 当前问题

#### 一、前后台混挂
- 报销、收入结算、支出结算、发票管理、往来账款 属于财务业务。
- 凭证、帐簿、报表、会计处理、期末结转、资产 属于财务核算。
- 当前全部混在财务一级下。

#### 二、同义入口并存
- 资金 / 资金管理
- 报表 / 报表（不同入口形态）

#### 三、非财务本域入口混入
- 工资管理 应迁出到人力资源。

#### 四、配置入口未分层
- 设置、业务维度 未区分财务内部配置与平台配置。

## 4. 财务目标结构

财务管理一级下，正式重构为两个二级域：

## 4.1 财务业务

承接所有前台单据流与结算流：

- 日常费用管理
  - 借支申请
  - 开支审计
  - 费用报销
  - 付款申请
  - 私车公用
  - 差旅餐补
  - 员工借款
- 项目财务管理
  - 临时费用审核
  - 项目采购审核
  - 现场成本预算
  - 开支费用统计
- 收入结算
- 支出结算
- 资金管理
- 发票管理
- 往来账款

## 4.2 财务核算

承接所有后台账务与报表能力：

- 会计处理
  - 凭证
  - 报表
  - 资产
  - 资金
  - 账簿
- 账户管理
- 基础设置
- 基础数据

## 5. 财务迁移处理原则

### 原则一：先按业务域重挂，不先重写页面
优先改菜单归属、路由归属、面包屑归属。

### 原则二：先收口入口，再逐步清理旧入口
旧入口短期允许过渡访问，但财务主导航只认目标结构。

### 原则三：工资管理先迁出
工资管理不继续留财务域，直接纳入人力资源的薪酬管理。

### 原则四：不保留财务一级下重复同义目录
例如：
- 资金 / 资金管理 只保留一个正式业务入口
- 报表只保留在财务核算域内的正式入口

## 7. 财务路由迁移方案

## 7.1 路由迁移目标

本次不单独做旧新映射表，而是直接定义财务模块的迁移策略：

1. 菜单入口按目标财务树重挂。
2. 页面路由按新归属重新整理。
3. 旧财务路径仍允许短期过渡访问。
4. 面包屑与标签页以新归属为准。

---

## 7.2 路由迁移分层

### 第一层：菜单路由层
职责：
- 决定财务页面从哪个菜单入口打开
- 决定页面属于财务业务还是财务核算

### 第二层：页面路由层
职责：
- 决定页面真实访问路径
- 决定是否复用原组件
- 决定是否保留旧路由跳转

### 第三层：跳转兼容层
职责：
- 待办跳转
- 通知跳转
- 报表跳转
- 收藏跳转
- 快捷入口跳转

---

## 7.3 财务路由实施规则

### 规则一：页面组件优先复用
第一阶段不大量重写组件，优先复用现有财务页面。

### 规则二：菜单归属改了，面包屑必须跟着改
不能只改左侧菜单，不改页面导航上下文。

### 规则三：新财务导航只认新归属
即使旧路径还能打开，页面顶部归属也必须显示为：
- 财务业务
- 财务核算

### 规则四：工资管理路由从财务域剥离
工资管理不再从财务菜单进入。

---

## 7.4 财务路由迁移清单（模块内嵌版）

### 财务业务类
- reimbursement → 财务业务 / 日常费用管理 / 费用报销
- revenue / settlement → 财务业务 / 收入结算
- payment / settlement → 财务业务 / 支出结算
- bill → 财务业务 / 发票管理
- 往来账款相关页面 → 财务业务 / 往来账款
- funds（业务资金视角） → 财务业务 / 资金管理

### 财务核算类
- Voucher → 财务核算 / 会计处理 / 凭证
- reports → 财务核算 / 会计处理 / 报表
- assets → 财务核算 / 会计处理 / 资产
- ledger → 财务核算 / 会计处理 / 账簿
- account → 财务核算 / 账户管理
- period → 财务核算 / 基础设置 / 期末结转
- settings → 财务核算 / 基础设置
- dimension/result → 财务核算 / 基础设置 或 系统管理 / 业财维度配置（最终确认后定）

### 迁出类
- cashier（工资管理） → 人力资源 / 薪酬管理

## 8. 财务前端改造范围

## 8.1 必改内容

- 财务面包屑
- 财务标签页归属
- 财务快捷入口归属

## 8.2 暂不大改内容

- 核算规则底层实现

---

## 9. 财务代码实施顺序

### 第 1 步：整理财务目标菜单结构
在前端先建立：
- 财务业务
- 财务核算

### 第 2 步：重挂财务页面入口
把现有页面先接到新菜单结构下。

### 第 3 步：统一面包屑与标签页
让财务页面打开后全部显示目标归属。

### 第 4 步：迁出工资管理
工资管理从财务中拆出，归人力资源。

### 第 5 步：验证跳转场景
- 待办
- 通知
- 报表
- 收藏
- 快捷入口

---

## 10. 财务联调清单

以下内容必须全部通过，财务样板才算完成：

1. 财务业务菜单显示正确
2. 财务核算菜单显示正确
3. 报销页面打开正确
4. 收入/支出结算打开正确
5. 发票管理打开正确
6. 往来账款打开正确
7. 凭证页面打开正确
8. 报表页面打开正确
9. 帐簿页面打开正确
10. 账户管理打开正确
11. 期末结转打开正确
12. 工资管理不再从财务进入
13. 面包屑显示为新归属
14. 标签页归属不混乱
15. 待办与通知跳转不出错

---

## 11. 财务样板完成标志

满足以下条件即视为财务样板模块完成：

- 财务目标导航可用
- 财务菜单归属正确
- 财务主要页面可从新入口打开
- 财务面包屑与标签页正确
- 工资管理已迁出财务
- 财务路由迁移方法可复制到其他模块

---

## 12. 财务样板完成后的复制顺序

财务完成后，按以下顺序复制方法论：

1. 人力资源
2. OA办公
3. 工作台

复制内容保持一致：
- 现状结构拆解
- 目标结构定义
- 路由迁移清单
- 前端改造范围
- 联调清单
