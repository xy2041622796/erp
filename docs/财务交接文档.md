## 2. 财务整体业务主线

财务系统的核心不是单个页面，而是一条完整的数据链路。

### 2.1 建账和基础配置

财务启用前，需要先完成基础设置：

1. 创建或选择当前账套。
2. 初始化或维护会计科目。
3. 设置科目编码规则。
4. 维护凭证字。
5. 维护币别。
6. 维护辅助核算项目。
7. 维护资金账户。
8. 录入科目期初余额。
9. 录入期初业务数据。

这些配置决定后续凭证、账簿、报表、资金流水、结账等模块能否正常运行。

### 2.2 日常财务处理

日常处理主要有两类来源：

第一类是手工录入：

- 手工新增凭证。
- 手工录入现金日记账。
- 手工录入银行日记账。
- 手工维护收付款、发票、报销、资产等业务数据。

第二类是业务生成：

- 现金日记账生成凭证。
- 银行日记账生成凭证。
- 收款提交生成凭证。
- 付款提交生成凭证。
- 固定资产折旧生成凭证。
- 固定资产变动生成凭证。
- 期末结转生成凭证。
- 部分业务动作生成财务维度数据。

### 2.3 账簿和报表

凭证保存后，账簿和报表会基于凭证明细、科目、期间、期初余额进行取数。

主要结果包括：

- 明细账
- 总账
- 科目余额表
- 科目汇总表
- 序时账
- 往来账
- 核算项目明细账
- 核算项目余额表
- 资产负债表
- 利润表
- 现金流量表
- 标准现金流量表
- 费用明细表
- 部门利润表
- 项目利润表

### 2.4 期末处理

月末或会计期间结束时，需要处理：

1. 期末检查。
2. 检查未完成的凭证、收付款、结算或异常数据。
3. 结转损益。
4. 生成结转凭证。
5. 结账。
6. 必要时反结账。

结账后，当期凭证原则上不能随意修改。

## 3. 账套管理

### 3.1 功能定位

账套是财务系统的数据隔离单位。不同账套下的科目、凭证、期初余额、账簿、报表、资金流水等数据应独立管理。

### 3.2 已完成内容

已经完成以下功能：

- 账套列表查询。
- 新增账套。
- 编辑账套。
- 删除账套。
- 获取当前账套。
- 财务页面顶部或公共位置切换账套。
- 财务接口根据当前账套处理数据范围。
- 账套下拉组件封装。
- 账套状态管理封装。

### 3.3 操作流程

正常使用流程：

1. 用户进入财务系统。
2. 系统读取当前账套。
3. 页面根据当前账套加载财务数据。
4. 用户可以通过账套下拉切换账套。
5. 切换后，凭证、科目、账簿、报表等页面重新按当前账套查询。

### 3.4 关联影响

账套影响以下模块：

- 会计科目
- 凭证
- 期初余额
- 现金日记账
- 银行日记账
- 资金账户
- 账簿
- 财务报表
- 期末处理
- 固定资产
- 收付款
- 财务维度

### 3.5 关键文件

- 页面：`src/views/finance/settings/accountset/index.vue`
- 页面：`src/views/finance/settings/accountsets/index.vue`
- 接口：`src/api/erp/finance/settings/accountset/index.ts`
- 组件：`src/components/account-set/AccountSetDropdown.vue`
- 状态：`src/store/account-set.ts`
- 工具：`src/utils/accountSet.ts`

### 3.6 注意

- 财务问题首先要确认当前账套是否正确。
- 不同账套数据不要混查、混写。
- 后续新增财务接口时，要确认是否需要传账套信息。
- 如果出现“数据为空”或“数据串账”，优先排查当前账套状态。

### 3.7 验收点

## 4. 会计科目

### 4.1 功能定位

会计科目是财务核算的基础。凭证录入、账簿查询、报表取数、资金账户、期初余额、辅助核算都依赖会计科目。

### 4.2 已完成内容

已经完成以下功能：

- 科目树展示。
- 科目分页或列表查询。
- 一级科目维护。
- 下级科目维护。
- 科目新增。
- 科目编辑。
- 科目启用和停用。
- 科目删除。
- 删除科目前检查影响。
- 检查科目是否被凭证使用。
- 查询指定科目下是否有凭证明细。
- 将凭证明细迁移到其他科目。
- 初始化当前账套科目。
- 重置当前账套科目模板。
- 重新初始化财务账套。
- 科目编码规则读取。
- 科目编码规则保存。
- 根据编码长度识别科目级次。
- 根据上级科目生成下级科目编码。
- 科目导入模板下载。
- 科目 Excel 导出。

### 4.3 操作流程

新增科目流程：

1. 进入会计科目页面。
2. 选择新增一级科目或新增下级科目。
3. 系统根据科目编码规则生成或校验科目编码。
4. 填写科目名称、科目类型、余额方向、辅助核算等信息。
5. 保存科目。
6. 凭证录入页面可以选择新增后的科目。

删除科目流程：

1. 用户点击删除科目。
2. 系统检查该科目是否存在下级科目。
3. 系统检查该科目是否被凭证、期初、资金账户或其他业务使用。
4. 如果存在使用记录，需要提示影响，不能直接删除或需要先迁移。
5. 确认无影响后才能删除。

### 4.4 关联影响

科目影响以下内容：

- 凭证明细的科目选择。
- 明细账、总账、余额表取数。
- 资产负债表、利润表、现金流量表取数。
- 资金账户对应科目。
- 现金日记账和银行日记账生成凭证。
- 固定资产生成折旧凭证。
- 收付款生成凭证。
- 期末结转。
- 辅助核算。

### 4.5 关键文件

- 页面：`src/views/finance/settings/project/index.vue`
- 页面配置：`src/views/finance/settings/project/data.ts`
- 接口：`src/api/erp/finance/settings/project/index.ts`
- 科目编码规则：`src/api/erp/finance/settings/project/subject-code-rule.ts`

### 4.6 注意

- 科目编码规则不要随意修改，已经有凭证后修改规则风险很高。
- 已使用的科目不要直接删除。
- 科目余额方向会影响账簿和报表展示。
- 现金、银行类科目会影响资金模块和现金流量表。
- 损益类科目会影响利润表和结转损益。

### 4.7 验收点

- 新增一级科目成功。
- 新增下级科目编码正确。
- 科目停用后凭证页面不能正常选择或按规则受限。
- 删除已使用科目时有拦截或影响提示。
- 科目新增后账簿查询能识别。
- 科目导出正常。

- 恢复凭证。

- 根据日期获取下一张凭证编号。
- 保存凭证主表。
- 保存凭证明细。
- 保存凭证明细辅助核算。
- 批量处理凭证。
- 凭证打印。
- 凭证摘要维护。
- 凭证科目选择。
- 借方金额、贷方金额录入。
- 借贷平衡处理。
- 凭证编号相关数据同步。
- 解析凭证分录。
- 构建凭证摘要。
- 现金日记账生成凭证。
- 资金流水关联凭证。
- 资金流水解绑凭证。

### 6.3 操作流程

手工新增凭证流程：

1. 进入凭证页面。
2. 点击新增凭证。
3. 选择凭证日期。
4. 系统根据日期和凭证字生成凭证号。
5. 填写摘要。
6. 选择会计科目。
7. 填写借方金额或贷方金额。
8. 如科目需要辅助核算，填写辅助核算信息。
9. 检查借贷是否平衡。
10. 保存凭证。
11. 保存后账簿和报表可以取到该凭证数据。

编辑凭证流程：

1. 进入凭证列表。
2. 打开已有凭证。
3. 修改摘要、科目、金额或辅助核算。
4. 保存主表和明细。
5. 同步更新相关账簿和报表数据。

删除凭证流程：

1. 用户删除凭证。
2. 凭证进入回收站。
3. 回收站内可以恢复。
4. 必要时可以永久删除。

### 6.4 关联影响

凭证影响以下模块：

- 利润表

- 银行日记账

## 37. 重点风险点

### 37.1 账套风险

财务数据必须按当前账套隔离。出现数据为空、数据不一致、数据串账时，优先检查当前账套。

### 37.2 科目风险

科目被凭证、资金账户、期初余额使用后，不能随便删除或改编码。

### 37.3 凭证风险

凭证影响所有账簿和报表。凭证保存逻辑改动后，要回归所有核心账表。

### 37.4 期间风险

已结账、已结转期间不应允许随意修改凭证。期末处理相关改动要格外谨慎。

### 37.5 金额风险

财务金额不能随意用浮点数直接计算，容易出现精度问题和 `-0.00`。

### 37.6 日记账重复插入风险

现金日记账和银行日记账历史上重点修过编辑保存重复新增的问题。后续改动时必须重点验证。

### 37.7 凭证关联风险

资金流水、收付款、固定资产等生成凭证后，业务单据和凭证之间的关联字段要一致。

### 37.8 维度规则风险

维度规则变更后，历史数据是否重算需要业务确认，不能默认覆盖历史结果。

### 37.9 主单明细风险

发票、收付款、工资、固定资产等模块很多是主单和明细分开保存，修改时不能只验证主单。

### 37.10 动态菜单风险

有些页面不一定出现在静态路由里，可能由后端菜单或动态权限控制。排查入口时要同时看菜单配置。

## 39. 后续开发原则

1. 不要重新设计目录结构，继续使用现有 `src/views/finance` 和 `src/api/erp/finance`。
2. 新增页面优先复用已有页面结构。
3. 新增接口优先放在对应业务目录下。
4. 金额处理优先复用现有金额工具。
5. 账套相关逻辑优先复用现有账套组件和状态。
6. 科目、凭证、期初、期间、报表相关修改必须做全链路回归。
7. 资金流水修改必须验证新增、编辑、保存、删除、生成凭证、解绑凭证。
8. 主单和明细分开保存的模块，必须同时验证主单和明细。
9. 修改页面后同步维护对应 `skill.md`。
10. 不建议绕过业务接口直接改财务核心数据。

## 40. 接手顺序

建议按以下顺序接手：

1. 先熟悉账套管理。
2. 再熟悉会计科目和科目期初。
3. 再熟悉凭证管理。
4. 再熟悉现金日记账和银行日记账。
5. 再熟悉总账、明细账、科目余额表。
6. 再熟悉资产负债表、利润表、现金流量表。
7. 再熟悉期末检查、结转损益、结账、反结账。
8. 再熟悉收款、付款、发票、固定资产。
9. 再熟悉工资、维度、报销和项目财务。
10. 最后看业务标准化和字段映射。

核心主线是：

账套 → 科目 → 期初 → 凭证 → 账簿 → 报表 → 期末

这条主线跑通后，再看资金、收付款、资产、工资、维度等扩展模块会更容易。
